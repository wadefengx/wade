# 经验教训

## 2026-08-01 Go 安装 404(续)

### L34: Go 版本解析三连坑
`wade go install 1.23` 404 的根因链:
1. **无 ResolveVersion**: 直接拼 `go1.23.windows-amd64.zip`(Go 文件名必须带 patch: `go1.23.12.windows-amd64.zip`)
2. **go.dev JSON API 默认只返回最近两个大版本**(1.26/1.25)——`1.23` 查不到。但**旧版本文件还在**(HEAD 200),只是 API 不列。用 `?mode=json&include=all`(357 版本)解决
3. **cobra 隐式子命令陷阱**: `wade go mirror aliyun` 中 `aliyun` 不是子命令(`use` 才是),cobra 回落父命令 RunE → 显示当前源而非切换。**"显示当前源"的输出就是证据**

### L35: 预设镜像会死,要实测
npmmirror/aliyun 的 Go 镜像 404(pip 的 aliyun 却是活的 200)。**presets 里的 URL 不是永恒的**——发布前对每个预设做 HEAD 验证,失效的移除(比报错给用户好)。验证方式: HEAD 请求具体文件而非目录页(目录页可能 200 但文件 404)。

### L36: 验证下载 URL 要 HEAD 具体文件
`wade go mirror test` 测的是目录 URL 延迟,不证明文件可下。验证镜像有效性 = HEAD `mirror/<version>.<platform>.<ext>` 具体文件。
